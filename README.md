# BLUE-v · 多账号 WhatsApp 工作台

Node.js 24 + **WA-JS 4.7.1** + Puppeteer + Chromium + Express + SQLite。提供用户注册登录、超级管理员订阅授权、多号码扫码连接、实时聊天和可配置自动回复。界面参考 WhatsApp Web 的会话列表与聊天布局，本项目为独立产品，与 WhatsApp 无隶属关系。

## 套餐与权限

| 套餐 | 默认可用号码额度 |
| --- | --- |
| 基础 `basic` | 1 |
| 高级 `pro` | 5 |
| VIP `vip` | 10 |

用户自由注册，默认没有使用权限。超级管理员登录后在「用户与订阅」中勾选开通权限、选择套餐、自定义可用号码数量（0–1000）、设置到期时间并保存；默认提供 30 天日期，可自行调整。订阅由管理员人工开通、续期和停用，没有自动收款或支付订阅功能。

- 普通用户不能新增号码，由管理员在「托管号码」中添加、扫码并分配。升级前已有的自有号码保持原来的归属、登录目录和聊天能力，无需重新扫码。
- 自定义数量优先于套餐默认额度，自有号码与分配号码合计计入额度，未连接号码也占用名额；设置为0时不可使用号码。旧用户未设置自定义额度时沿用原套餐额度。
- 停用或到期后禁止连接、收发消息和自动回复。后台最长 5 秒检查一次已有连接，各 API 与发送操作实时检查权限；已经开始的网络请求无法撤回。
- 降低额度后只保留最早添加的配额内号码可用，超出的连接停止、数据保留；托管号码由管理员收回，自有号码的连接和删除也由管理员管理。
- 用户的号码、WhatsApp 凭据、聊天记录、图片和自动流程分别隔离。超级管理员可管理用户订阅，不提供代登录查看用户聊天功能。
- 授权操作保存最近的审计记录。超级管理员使用同一登录页面，通过服务端角色控制进入后台。

## 本地运行

需要 **Node.js 24 或以上与 Chromium**，使用内置 SQLite。Docker 镜像会安装 Chromium，本机请先安装系统 Chromium（Debian/Ubuntu 可使用系统软件包），并通过 `CHROMIUM_PATH` 指定可执行文件。每个号码独立运行浏览器并使用持久化档案。首次启动需要设置管理员账号（4–64 位字母、数字、点、横线或 @）与至少 6 位密码：

```sh
npm ci
# 在当前终端安全设置 ADMIN_USER 和 ADMIN_PASSWORD，勿将密码提交到 Git。
npm start
```

默认监听本机 `127.0.0.1:3000`。管理员在网页登录后进入「托管号码」添加并扫码，再分配给已开通的用户；已有自有号码的连接由管理员在号码管理页操作。使用手机 WhatsApp 的「已关联的设备」扫码。新号码需要独立扫码；仅在 WhatsApp 页面就绪且已取得有效的当前登录账号标识时显示已连接，没有账号标识不会保存登录成功状态或允许发送；扫码后，号码选择框、顶部「我的号码」和连接窗口会显示含国家区号的实际 WhatsApp 手机号。协议仅返回 LID 时会读取当前登录账号的号码映射并自动重试；无法解析时明确提示，不把内部 ID 当成手机号。工作台只显示当前用户、当前号码的连接状态。退出或切换登录身份时会清除聊天列表、消息预览、聊天标题、管理页和附件草稿，即使下一位用户没有号码也不会保留旧页面内容；较早的请求和启动身份检查不能恢复旧账号。新增号码时会忽略较早的列表响应，避免被切回旧号码。相同浏览器的普通标签页共享登录 Cookie，切换登录账号后，旧标签页的操作会被拒绝并要求重新登录；需要同时登录多个平台账号时请使用不同浏览器配置文件或不同浏览器。可以切换号码和会话，新建聊天、发送文本或配置自动流程。注册密码支持 6–128 个字符。聊天输入框旁的「＋」可选择图片、视频、音频和文件（单个最大 20MB），支持附带文案；发送失败保留附件供重试。上传文件保存在当前号码的媒体目录，账号之间隔离。管理员可在用户列表点击「修改 / 重置密码」，设置新密码或生成随机密码；操作会撤销目标用户的全部登录，并记录不含密码的审计日志。随机密码仅在当前弹窗显示，请复制保存。

`npm run dev` 开发；`npm run check && npm test` 验证。支持 `HOST`、`PORT`、`DATA_DIR`、`AUTO_CONNECT`、`PUBLIC_ORIGIN` 和 `CHROMIUM_PATH`，完整生产设置见 [Railway 部署说明](RAILWAY.md)。程序不会自动加载 `.env`，`.env.example` 仅作为变量参考。

## 数据与登录

- `DATA_DIR/blue-v.sqlite`：用户、scrypt 密码散列、会话令牌散列、订阅、号码、每个号码最新 500 条消息及授权审计。消息在重新部署后保留；不是 WhatsApp 完整历史同步。登录后自动读取 WhatsApp 网页可用的最近 50 个会话，每个最多 10 条；也可点击「同步消息」重试。历史导入不触发自动回复。
- `DATA_DIR/tenants/<用户ID>/<号码ID>/browser-profile/`：敏感浏览器登录档案；同目录下 `wajs-session.json` 标记已登录、`flows.json` 保存流程、`media/` 保存图片。不要编辑或共享浏览器档案。
- 平台登录使用 HttpOnly、SameSite=Strict Cookie，生产环境再加 Secure，7 天有效；退出登录立即撤销此登录会话。平台退出不停止仍在有效订阅中的 WhatsApp 自动回复。
- 首次运行的 `ADMIN_USER` / `ADMIN_PASSWORD` 用于创建超级管理员。数据库已有管理员后，不会通过环境变量覆盖密码；应妥善保存账号及数据备份。
- 删除号码会删除该号码本地数据。若需撤销 WhatsApp 手机端关联，请在手机已关联设备中移除。重置号码会话仅清除该号码凭据。
- 会话消息与二维码均需登录且拥有此号码和有效订阅才可读取。请使用 HTTPS；不要将数据目录发布为静态文件。

只支持单个服务实例，请勿增加 Railway 副本、Node 集群或多个进程共用登录目录。备份时先停止服务，完整备份数据目录，包含 SQLite 的 WAL/SHM 文件和各号码凭据。

## 自动回复

选择号码后点击左侧「自动化流程」，载入示例，修改节点文案、图片和选项，启用并保存。每个号码单独配置，切换号码前请保存编辑。

流程工具栏可选择多个公共示例。超级管理员点击「载入并编辑示例」会进入公共示例编辑模式，可修改节点、图片、选项及名称，再点击「保存公共示例」更新。界面显示版本号，旧页面不能覆盖其他页面已更新的版本；也可「另存为新示例」新增模板或删除。要使用到自己的号码，请选择「载入到当前号码」，启用并保存号码流程。所有用户均可载入示例。载入到号码时只替换编辑内容，需启用并保存号码流程才生效；公共示例更新不影响已保存的号码流程。模板保存在 SQLite，图片保存在 `DATA_DIR/template-media`，随数据卷持久化。

例如：「你好 / 菜单 / hi」→ 欢迎菜单 → 产品介绍 / 联系顾问 → 对应回复。支持 PNG、JPEG、WebP 图片（最大 5MB）、图片文案、最多 3 个选项、多级分支与返回菜单。

回复文案及图片文案支持 `{full_name}`（对方 WhatsApp 名称）和 `{phone_number}`（含国家区号的手机号，不带 `+`），例如 `Dear user {full_name}, hello! {phone_number}`。发送时读取对方资料并替换，不改变已保存模板；名称不可用时回退手机号或「客户」。LID 会通过 WA-JS 联系人映射获取真实手机号；无法取得时显示「未知号码」，不会把 LID 当作手机号。变量不用于按钮名称或触发词。

只有第一个节点是入口，可选择「关键词触发」或「任意内容触发」。关键词完整匹配，忽略大小写和首尾空格；后续回复节点不能设置触发词，只能通过前面节点的选项进入，也可用选项返回入口。原生按钮模式需要点击按钮；兼容模式允许回复序号或选项文字。客户当前步骤保留 30 分钟，进行中不会因普通消息重新触发入口。原生按钮按原菜单查找分支，可点击此前菜单，不受当前步骤或 30 分钟会话到期限制；发送菜单及分支快照随保留的消息持久化（每号码最新 500 条消息），重启后仍可用。旧版本菜单没有分支快照时，仅在按钮文字完整匹配现有节点时兼容；已删除的目标节点不会执行。兼容模式的数字或文字选项仍按当前步骤解释；保存流程、断开或重启会重置。旧流程加载时会忽略分支节点原有的触发词，下次保存后写入新格式。仅处理实时个人消息，忽略群聊、自己发送和过旧事件；持久化消息 ID 及进程内过滤用于避免重复处理。

原生按钮使用 WA-JS 的 `sendTextMessage` / `sendFileMessage` 接口，保持上游 Native Flow 封装。最多 3 个文字回复按钮；图片附带最多 2 个按钮，3 个选项时先发图片，再发单独的按钮菜单。按钮仍为兼容功能，服务端提交成功或收到发送 ACK 都不代表 iPhone 已显示；需真实账号验证。不兼容时使用数字菜单。项目尚未接入 Meta 官方 WhatsApp Cloud API。

## API 概览

认证使用网页登录返回的 Cookie，写请求需符合 `PUBLIC_ORIGIN` 同源检查：

- `POST /api/auth/register`、`POST /api/auth/login`：`{username,password}`。
- `GET /api/auth/me`、`POST /api/auth/logout`：当前用户与退出。
- `GET /api/admin/users`、`PATCH /api/admin/users/:id`：超级管理员列表及授权，写入 `{enabled,plan,limit,expiresAt}`，时间为 ISO 字符串。
- `GET /api/accounts`：自己的自有/获分配号码列表；`POST` 不再开放新增。`DELETE /api/accounts/:id` 仅允许管理员删除自己的原有号码。
- `GET/POST /api/admin/numbers`：托管号码列表与新增 `{label}`；`GET /api/admin/numbers/:id/state` 只返回连接元数据，`POST .../connect` 扫码连接，`PATCH .../assignment` 使用 `{userId}` 分配或 `{userId:null}` 收回；`DELETE` 允许管理员删除待分配、已分配及原有自有号码。
- `/api/accounts/:id/state`、`events`、`connect`、`logout`、`messages`、`flows`、`media`：指定号码的状态、实时事件、关联设备、退出 WhatsApp、消息及自动回复资源。旧的全局单账号 API 已移除。
- `GET /healthz`：公开的进程健康检查，不代表 WhatsApp 已连接。

## 从 Baileys 版本升级

升级前停止服务并完整备份 `DATA_DIR`。本版本保留用户、套餐、号码、聊天记录和原有流程/图片路径，不需要新建用户或号码。**Baileys 的 `auth/` 凭据不能转换为 WA-JS 浏览器档案，每个号码必须重新扫码。** 旧凭据会保留，程序不会读取或删除它们；确认迁移成功后可由管理员安全清理。不要把旧 `auth/` 复制到 `browser-profile/`。

若来自最早的全局单账号版本，旧根目录 `flows.json` 和 `media/` 可在停止服务及备份后复制到管理员新建号码的目录中，不覆盖已有文件；登录仍需重新扫码。`AUTH_DIR` 不再使用。

## Chromium 运行说明

- Docker 镜像内置 `/usr/bin/chromium`、CA 证书和 tini，用于启动浏览器并回收子进程；`CHROMIUM_NO_SANDBOX=true` 针对本容器运行环境设置，本机支持浏览器沙箱时不要启用它。
- 每个号码占用一个浏览器进程组，内存/CPU 高于原来的 WebSocket 方案。套餐限额仍为 1/5/10，但服务资源必须支撑实际在线数量，不要启用服务休眠。
- `AUTO_CONNECT=true` 仅自动恢复 WA-JS 已成功登录、有会话标记、仍有有效订阅且在配额内的号码。无标记的新号码不会在后台自动启动扫码浏览器。
- 默认使用 `HTTPS_PROXY` / `https_proxy`；可用 `CHROMIUM_PROXY_SERVER` 指定浏览器代理。证书信任错误需通过部署机器或 Chromium 支持的信任库正确安装代理 CA 解决，不关闭 TLS 验证。
- 停用、到期、删除、重置与服务退出都会关闭对应浏览器。重置会删除浏览器档案，需重新扫码；停用保留档案以便恢复。

## 验证范围

测试覆盖注册、认证、角色限制、套餐默认及自定义配额、禁止普通用户新增、托管号码转交/收回和旧数据迁移、跨用户资源隔离、停用与到期撤销事件流、配置/消息持久化、自动回复分支、WA-JS 消息映射、按钮参数及浏览器关闭生命周期。浏览器检查覆盖注册授权、号码切换、流程隔离、聊天布局和移动端显示。`npm run test:browser` 需要 Chromium，包含管理员保存公共示例、新注册用户载入最新文字/图片/分支的网页回归检查；也会加载真实固定版本 WA-JS 脚本，并用测试替身验证二维码事件及图片/文字按钮调用，不连接真实账号。真实扫码、多号码在线、消息投递和原生按钮显示需要可访问 WhatsApp 的网络及用户手机参与，自动化测试不代表这些行为已通过。

实时接收同时监听 WA-JS 新消息事件、底层消息集合变更，并周期检查最近缓存以补回漏发事件。未解密占位消息不会占用消息 ID。页面显示接收通道就绪状态和最近收信时间；悬停可查看收到的事件及未解析计数。历史导入与实时补读分别处理，旧历史不触发自动回复。

## 接收媒体消息

收到的新图片（不超过 5MB）会自动下载原图并缓存，点击图片可查看原图。语音、音频、视频、文件及较大图片提供加载按钮，单文件最大 20MB；下载后可播放音视频或下载文件。语音不会自动转成文字。旧消息请先点击「同步消息」补充媒体信息；WhatsApp 已失效或无法下载的原文件仍需在手机查看。缓存保存在各号码的数据目录，并通过账号权限校验读取。

## 发送语音、视频与消息操作

聊天输入框旁的麦克风用于录音，再次点击停止，点击发送后以 WhatsApp 语音消息发送；录音最长 5 分钟、最大 20MB。需 HTTPS 和浏览器麦克风授权，取消草稿、切换会话或账号会停止录音。视频按钮选择 MP4/WebM（最大 20MB），其他附件仍可通过加号发送。

每条消息可转发到当前号码的已有会话，或输入含国家区号的新号码。自己发送的消息可撤回；仅在 WhatsApp 确认撤回后更新界面，超出上游时限会提示失败。源消息必须仍保留在工作台及 WhatsApp 中，部分特殊消息不支持转发。

实时语音通话尚未接入。WA-JS 提供拨号接口，但此项目的 WhatsApp 浏览器运行在云端，尚无用户浏览器与云端之间的双向音频传输；仅调用拨号接口无法实现麦克风和扬声器通话。当前请使用手机 WhatsApp 通话。

## 聊天列表与提醒

聊天列表显示 WhatsApp 名称和手机号；LID 联系人会尝试解析真实手机号，未取得时显示「手机号待解析」。选择聊天后点击右上角「备注」可保存或清除备注，原名称仍显示在列表第二行。备注和工作台已读时间按用户所拥有的号码独立持久化，不修改手机 WhatsApp 联系人或上游已读回执。

未读会话显示计数圆点和头像脉冲提示。进入可见且获得焦点的聊天后标为已读。点击列表上方「开启声音」后，当前号码的新消息可触发短提示音；首次加载、历史同步及重复状态更新不响铃，正在阅读的聊天也不响铃。声音受浏览器后台播放限制，未读标记仍保留。右上角 × 关闭当前聊天视图，保留聊天记录。聊天列表、消息区和其他内容页独立滚动，主菜单固定。

## 消息发送与已读回执

自己发送的消息显示真实回执：时钟表示等待发送或尚未同步，单勾表示已发送到 WhatsApp，灰色双勾表示已送达，蓝色双勾表示已读或语音已播放。明确失败显示红色提示，悬停查看原因。消息回执实时更新并持久化，手动同步也会补充历史消息的回执；尚无回执的旧消息不会假定为已发送。

单勾不能判断对方是否拉黑或拒收。对方离线、关机、网络异常也会导致未送达；关闭已读回执可能导致看不到蓝色双勾。WhatsApp 未提供可靠的被拉黑检测，界面不会将未送达误判为拉黑。群聊以 WhatsApp 返回的汇总回执为准。

## 管理员托管与分配号码

管理员进入「用户与订阅 → 托管号码」，点击「添加托管号码」，连接并扫码后在列表选择用户，保存分配。选择「待分配 / 收回」可撤销授权，也可转交给其他有效订阅用户；转交前界面会提示新用户可以读取该号码已有聊天、附件、备注及流程。数量不足时不能新增分配；已有自有号码也计入数量。只允许分配管理员新建的托管号码，不接管普通用户原有自有号码。

号码管理页仅请求状态、号码、所属用户和二维码，不加载聊天内容或订阅消息流；管理员也无法通过普通聊天 API 查看托管号码内容。托管号码从管理员的聊天号码列表排除，用户的工作台显示自有及获分配的号码。普通用户没有任何号码管理权限，不能连接设备、重置会话或删除任何号码，需联系管理员处理；已有自有号码保留归属和聊天能力，但普通用户的连接、重置及删除权限统一取消，由管理员在号码管理页操作。

收回/转交会等待已开始的号码操作完成（忙时提示稍后重试），更新授权并立即断开原用户的消息流，保留 Chromium 连接与原登录目录，无需移动凭据或重新扫码。待分配号码继续接收并保留记录，暂停自动回复。订阅停用或到期仍会停止相应用户的连接。服务器重启后是否自动恢复连接由 AUTO_CONNECT 控制；目录固定为最初创建者的路径，不能按当前使用人手动搬动文件。

升级会自动添加数据库字段，保留旧用户套餐、自有号码和登录档案；不修改任何用户密码。部署前应备份完整数据卷。

普通用户的状态接口和消息流不返回登录二维码。管理员可在号码管理页查看原有自有号码的连接元数据并执行连接、同步、重置和删除；原有自有号码不允许分配给其他用户，不改变其归属。

「同步消息」作为补拉近期记录和更新回执的功能，保留给普通用户；仅可同步本人自有或获分配、订阅有效且已连接的号码。连接、重置和删除仍仅限管理员。

## 卖家激活码（统一托管模式）

管理员新增托管号码时必须填写一个有效激活码。每码永久核销一次，创建号码与核销在同一个 SQLite 事务中完成；创建失败会回滚，重复提交或并发使用只会有一个成功。删除号码不会返还激活码，收回/转交不再收费，升级前已有号码不补收费。激活码属于持有码，不绑定购买人，卖家应逐个发放并保管明文库存。

初始1000码的**摘要批次**在 `activation-batches/initial.json`，服务启动时自动导入 `/data/blue-v.sqlite`；重复启动/导入不会恢复已用码。明文CSV独立交付给卖家，不提交仓库、不放入公共目录。数据库和审计只保存摘要、批次与核销记录，网页管理员没有生成或导入激活码的接口，也无法列出未使用的码。

卖家在自己控制的服务器或电脑上生成后续批次：

```sh
node scripts/generate-activation-codes.mjs 1000 /secure/blue-v-activation-exports
```

命令只输出批次号和文件路径。生成的CSV是发给客户的明文清单，JSON只含摘要。将JSON传到统一托管服务器的私有路径，再在服务目录执行：

```sh
DATA_DIR=/data node scripts/import-activation-codes.mjs /data/private-activation-batches/批次号.json
```

也可将 `ACTIVATION_CODE_MANIFEST` 设置为服务器上额外JSON文件的绝对路径，重启时导入。该路径未设置时仅自动导入初始批次。导入脚本必须使用生产服务实际挂载的数据卷；在本地导入本地数据库不会改变 Railway 数据。不要删除核销表或用旧数据库覆盖生产卷，否则可能恢复已使用激活码。备份时保留完整SQLite数据库。

此方案用于卖家统一托管、掌握服务器权限的业务。不要向客户提供生产服务器、数据库或部署权限；它不是防止服务器所有者修改源码的离线授权方案。

## 跨服务器复制公共示例

公共示例保存在各服务器的数据卷，新的独立服务器不会自动取得旧服务器修改。管理员可在自动回复页选择示例后点击「复制示例码」，也可在「超级管理员 → 跨服务器迁移示例」中选择示例导出；后者不需要先添加或连接任何 WhatsApp 号码。复制码包含已保存的名称、文案、变量、触发设置、按钮分支及完整图片，不包含登录凭据、聊天记录或激活码。未保存的编辑需先保存再导出。

在另一台服务器的同一区域，点击「粘贴复制码 / 上传示例」，粘贴 `BLUEFLOW1.` 开头的复制码并导入，或下载 `.blueflow` 文件后上传。图片较多时建议文件方式。导入生成新的示例ID和图片文件，不覆盖同名示例或已有流程；示例可供用户选择载入，仍需用户保存并启用号码流程才执行。源、目标服务器都需部署支持此格式的版本。

仅管理员可导入导出公共示例。每张图片最大5MB、总图片最大10MB，解压包最大16MB；文件/复制码最大22MB，超过限制需精简图片或拆分示例。损坏的码、无效图片或分支会被拒绝。

管理员在没有任何自有或获分配号码时，也可直接进入「自动回复流程」：系统载入公共示例编辑器，可编辑文案、触发方式、按钮分支，上传图片并保存/另存示例，亦可导入导出复制码。示例及图片通过独立管理员接口保存，不再依赖号码目录。公共示例本身不执行自动回复，因此「启用自动回复」和「载入到当前号码」在没有号码时禁用；用户载入到自己的号码并保存启用后才执行。

管理员可在号码管理列表直接删除已分配号码，无需先收回。确认提示会说明清除本地聊天、附件、流程和登录档案、撤销用户访问权限及激活码不返还。删除前会关闭浏览器并等待已开始的操作结束，删除后立即撤销消息流。普通用户无删除权限。此操作删除平台本地号码资料，不会注销手机上的WhatsApp账号。
